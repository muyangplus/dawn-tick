# 05 验证与质量

## 1. 验证入口

| 项 | 内容 |
|---|---|
| 命令 | `powershell -File tools/verify/verify-all.ps1` |
| 工作目录 | 仓库根 |
| 输出 | 逐项 `[PASS]` / `[FAIL]` / `[SKIP]`，末尾汇总 `PASS n / FAIL n / SKIP n` |
| 退出码 | 任一 FAIL 为 1，否则为 0 |
| 检查项 | 19 项，分 9 段执行 |

- 未构建的产物项记 `[SKIP]`，并在同一条里给出对应构建命令。
- 产物项报体积：exe 与安装包按 MB，Web 报最大分包 KB，Rust 报 `passed=<n>`。

## 3. 单元测试

| 套件 | 用例数 | 运行命令 |
|---|---|---|
| core | 246 | `pnpm -C packages/core test` |
| web | 155 | `pnpm -C apps/web test` |
| tools | 32 | `node --test tools/release/plan.test.mjs tools/release/build-stamp.test.mjs tools/release/ci-gate.test.mjs tools/release/changelog.test.mjs tools/design/check-a11y.test.mjs` |
| 全部 | 433 | `pnpm test` |

- 用例文件数：core 28 个、web 20 个、tools 5 个。
- 运行器为 `node --test`，依赖 Node 24 的原生类型擦除直接执行 `.ts`。
- core 用内存存储，web 用 `fake-indexeddb`，tools 覆盖发布规则与设计令牌。
- 单套件直跑：`node --test packages/core/test/<文件>.test.ts`。

## 5. schema 跨引擎校验

| 项 | 内容 |
|---|---|
| 命令 | `python tools/schema-check/validate_schema.py` |
| 方式 | 内存 SQLite，开启 `PRAGMA foreign_keys=ON`；先建表 `001_init`，再按序应用 `002_event_kinds`、`003_custom_time`、`004_timetable_entries`、`005_due_at_any`、`006_schema_version` |
| 结果 | 合计 43 项，通过 43 项；失败项逐行打印 `[FAIL]` 并退出码 1 |
| 覆盖 | 8 张表与列类型、周次位图手算、约束拒绝、迁移后数据保留、级联删除、假期来源优先级、提醒默认值 |

- Rust 侧 `cargo test` 另做一次 DDL 校验；Windows 侧由 `tauri-plugin-sql` 执行迁移。
- 已发布的迁移文件不得再改，否则老库启动失败。

## 8. CI 的三个 job

| job | 运行环境 | 步骤 |
|---|---|---|
| `node`（测试与类型检查） | ubuntu-latest、Node 24 | `pnpm install --frozen-lockfile` → `node tools/release/version.mjs --check` → `pnpm typecheck` → `pnpm test` |
| `schema`（数据模型跨引擎校验） | ubuntu-latest、Python 3.13 | `python tools/schema-check/validate_schema.py` |
| `rust`（Rust 壳与 DDL 校验） | windows-latest、stable 工具链 | `cargo check --all-targets` → `cargo test` |

- 触发：push 到 `dev` / `main` 与 `v*` 标签、PR 到 `dev` / `main`、手动触发。
- 并发键为 `ci-<ref>-<sha>`，同键取消进行中的运行。
- 权限为 `contents: read`；main 的分支保护要求这三个 job 全绿。
