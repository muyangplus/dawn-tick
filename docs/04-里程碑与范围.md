```
本期（离线单机版）                              下一期（多端同步版）
M0 方案确认 ✅ 已完成                            M7 服务端 + 账号体系
```

**M1–M6 为本期范围**；M7–M10 明确推迟到下一期（D3）。

### 技术栈基线（D24–D27）

| 端 | 技术 | 壳 |
|---|---|---|
| Web | React + TypeScript | 浏览器，SQLite-WASM + OPFS |

| Android | 同一套界面代码 | **Capacitor** |

### M1 仓库骨架 + 跨三端 SQLite
| 项 | 内容 |
|---|---|
| 交付物 | monorepo 结构；数据访问层；`001_init.sql` 迁移脚本与版本管理；单元测试框架 |
| **关键验收** | **同一份 DDL 在 Web(WASM) / Tauri(sqlx) / Capacitor 三端各跑通一次**（风险 R11 是本阶段最大不确定性） |
| 其他验收 | 一条命令建库并按迁移升级；数据模型 CRUD 单测通过（含 39 项校验中可复用的部分） |
| 依赖 | M0 定稿 |
| 需先装工具链 | Node（已有）；**Rust（Tauri 2 需要，≥1.90）**；**Android SDK + Gradle（Capacitor 需要）** |
| 风险 | 三端 SQLite 版本差异；OPFS 需要跨源隔离响应头，Web 端首次配置容易踩坑 |

### M2 课表核心
| 项 | 内容 |
|---|---|
| 交付物 | 周视图（CSS Grid 自绘）、今日视图、课程详情、颜色标记；**排课展开(expand)函数** |
| 完成判据 | 固定的测试样例（连续周次、双周、碎片周次、连堂、放假、调休补课、调课）渲染结果正确 |
| 依赖 | M1 |
| 风险 | 展开函数是项目最复杂逻辑（`01` 第 6 节）；四者叠加最易出 bug（R6） |

### M3 课表导入
| 项 | 内容 |
|---|---|
| 交付物 | ICS 导入导出、CSV/Excel 二维矩阵导入、手动添加；**教务抓取只留插件位不做实现**（D30） |
| 完成判据 | 每种格式有真实样例文件导入成功；重复导入幂等；ICS 往返不丢周次语义 |
| 复用组件 | `exceljs`(MIT) 读 Excel；`ical.js`(MPL-2.0) + `rrule`(BSD-3) 处理 ICS；**不用 SheetJS CE**；详见 `03` |
| 风险 | ICS 导出**单双周必须设 `WKST`**，否则在别的日历软件里整体错位一周；不连续周次需拆多个 VEVENT 或用 `RDATE`；矩阵解析的业务语义（节次行头、跨行跨列、多课格、文本周次）必须自写 |

### M4 课前提醒
| 项 | 内容 |
|---|---|
| 交付物 | 课前 5/10/15/30 分钟 + 自定义；节假日跳过（按 D22 优先级判定）；首次导入后再请求通知权限 |
| **分端实现** | Android：Capacitor 官方 `@capacitor/local-notifications`（申报 `USE_EXACT_ALARM`）<br>Windows：**常驻托盘 + 开机自启**（D29），应用内定时<br>Web：浏览器通知（能力有限，需明确告知用户） |
| 完成判据 | 各端在**应用未打开**时也能准时提醒；调休日不误提醒、放假不提醒 |
| 依赖 | M2、M3 |
| 风险 | **核心卖点，也是最大技术不确定性**；Web 端最弱，需在 UI 上如实说明 |
