## 1. 分期总览

```
本期（离线单机版）                         下一期（多端同步版）
M0 方案确认                                M7 服务端 + 账号体系
 └─> M1 仓库骨架 + 本地数据库                M8 增量同步 pull→push→pull
      └─> M2 课表核心（周视图/今日/详情）      M9 冲突解决（字段级 + 用户选择）
           └─> M3 课表导入（ICS/CSV/教务）    M10 调课 WebSocket 实时推送
                └─> M4 课前提醒
                     └─> M5 小组件（三端）
                          └─> M6 打磨与发布
```

**M1–M6 为本期范围**（离线优先、单机单用户）；M7–M10 明确推迟到下一期。

## 2. 里程碑明细

### M0 方案确认（当前阶段）
| 项 | 内容 |
|---|---|
| 交付物 | 本套文档定稿：数据模型（去 ⚠）、技术选型（定稿）、里程碑（定稿） |
| 完成判据 | 负责人逐条确认 `01-数据模型设计.md` 与 `02-技术选型对比.md` 中的待确认项 |
| 阻塞点 | **技术栈未定**（D2）→ 后续所有里程碑的排期都依赖它 |

### M1 仓库骨架 + 本地数据库
| 项 | 内容 |
|---|---|
| 交付物 | monorepo 目录结构；SQLite 建库与 migration 机制；数据访问层；单元测试框架 |
| 完成判据 | 一条命令可创建空库并按 migration 升级；数据模型表的增删改查单测通过 |
| 依赖 | M0 定稿 |
| 风险 | 若选 Flutter/Kotlin，需先安装工具链（见 `02-技术选型对比.md`） |

### M2 课表核心
| 项 | 内容 |
|---|---|
| 交付物 | 周视图、今日视图、课程详情、颜色标记；**排课展开(expand)函数**（周次/单双周/节次 → 具体课次） |
| 完成判据 | 固定的测试样例（含单双周、周次范围、连堂、调休）渲染结果正确 |
| 依赖 | M1 |
| 风险 | 「单双周 + 周次范围 + 调休 + 调课」叠加是最易出 bug 处（见 `01` 风险 R6） |

### M3 课表导入
| 项 | 内容 |
|---|---|
| 交付物 | ICS 导入导出、CSV/Excel 二维矩阵导入、手动添加、（教务系统在线抓取——**是否本期做待定**，见 Q-D4） |
| 完成判据 | 每种格式有真实样例文件导入成功；重复导入不产生重复数据（幂等性）；ICS 往返（导出再导入）不丢周次语义 |
| 依赖 | M2（需要展开函数校验导入结果） |
| 复用组件 | 调研结论（见 `03-开源组件调研.md`）：Excel 读用 `exceljs`(MIT)；ICS 用 `ical.js`(MPL-2.0) + `rrule`(BSD-3)；**不用 SheetJS CE**（强制 attribution + 离开 npm）；**教务抓取无现成组件** |
| 风险 | ①**教务系统适配不存在跨校通用库**，每校一份，且需要真实样例；②ICS 导出**单双周必须设 `WKST`**，否则在别的日历软件里会整体错位一周；③不连续周次集合需拆多个 VEVENT 或用 `RDATE` |

### M4 课前提醒
| 项 | 内容 |
|---|---|
| 交付物 | 课前 5/10/15/30 分钟 + 自定义提醒；节假日跳过；首次导入后再请求通知权限 |
| 完成判据 | 应用**未运行**时也能准时提醒（能力随技术栈受限，见 `02`）；调休日不误提醒 |
| 依赖 | M2、M3；节假日数据来源（`01` Q-A7） |
| 风险 | **核心卖点，也是最大技术不确定性**：Android 精确闹钟权限、iOS/Windows 后台限制 |

### M5 小组件（三端）
| 项 | 内容 |
|---|---|
| 交付物 | 下一节课、今日课表、一周概览、考试倒计时 |
| 完成判据 | 各端小组件在数据变化后能刷新到最新（Android 15 分钟周期；Windows 形态待定） |
| 依赖 | M2 |
| 风险 | **Windows 11 小组件面板对第三方限制严格**，可能只能退化为置顶悬浮窗；详见 `02-技术选型对比.md` |

### M6 打磨与发布
| 项 | 内容 |
|---|---|
| 交付物 | 空状态/错误态、数据导出备份、性能与体积优化、打包分发 |
| 依赖 | M2–M5 |

## 3. 优先级建议（⚠ 待你确认排序）

若你希望**尽快看到能用的东西**，我建议调整顺序为：
`M1 → M2 → M4（提醒）→ M3（导入）→ M5（小组件）`

理由：提醒是核心价值，且不依赖导入（手动添加几门课即可验证）。
但若你的首要痛点是「导课表太麻烦」，则保持 `M1 → M2 → M3 → M4` 原序。

**这一条必须由你选**，我不替你定。
