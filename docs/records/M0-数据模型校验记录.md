## 4. v1 → v2 校验的差异

| 项 | v1 | v2 |
|---|---|---|
| 表数 | 10 | **8**（删除 `course_adjustments`、`day_overrides`，并入 `events`） |
| 周次存储 | `week_start`/`week_end`/`week_type` + JSON `weeks` | **位图 `weeks_mask`**（不依赖 JSON 函数） + `weeks_raw` 保留原文 |
| 断言数 | 19 | **33** |
| 自定义周次查询 | `json_each`（依赖 JSON 函数，有 Android 兼容风险） | **位运算**（任何 SQLite 版本可用） |
| 调课/调休完整性 | 靠独立表的外键 | 靠 `events` 的**条件 CHECK 约束**（6 项，均已实测生效） |

---

## 5. 本次校验**未能**覆盖的部分

| 未覆盖 | 原因 |
|---|---|
| **「展开(expand)」逻辑**：把排课规则展开成具体课次，并叠加放假/调休/调课 | 属 M2 工作，是本项目最复杂的一段逻辑（见 `01` 第 5 节） |
| 「下一节课」查询与性能 | 同上；需 `time_slots × start_date` 计算绝对时刻 |
| ICS 导入导出往返一致性 | 依赖 RFC 5545 映射，见 `03-开源组件调研.md` 第 2 节（单双周必须设 `WKST`） |
| 真实教务系统导出的畸形数据 | 需要真实样例文件 |
| 并发写入 / 数据迁移 | M1 处理 |

---

## 6. 结论

1. 数据模型 **v2 技术可行性已验证（33/33）**，含「单表承载 7 种语义」这一由负责人决定的方案。
2. **位图编码减少了对外部函数的依赖**，同时消除了 v1 中 `json_each` 在 Android 上的兼容风险（风险 R7）。
3. 第 3 节样例建议直接转为正式单元测试，防止「周次集合 + 调休 + 调课」叠加时回归。
4. 校验脚本在 `tools/schema-check/`（非产品代码），建议保留为正式测试基础。
