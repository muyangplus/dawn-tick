# M1 — 存储抽象层重构记录

日期：2026-10-10
原因：负责人决定 Web 端改用 IndexedDB，各端使用各自最合适的底层存储，由统一抽象层与同一套同步逻辑保持一致。

## 1. 变更

| 项 | 变更前 | 变更后 |
|---|---|---|
| Web 存储 | SQLite-WASM + OPFS | IndexedDB（`idb` 封装） |
| 抽象层 | `SqlDriver`（SQL 语句接口） | `Storage` / `Collection<T>`（文档集合接口） |
| 业务逻辑位置 | `queries.ts` 的 SQL 查询 | `repository.ts` 的纯函数，全部端共用 |
| 同步 | 未实现 | `sync.ts`：pull → push → pull，附本机可跑的 `MemoryRemote` |
| SQL 建表 SQL | 三端共用 | 仅 Windows / Android 的物理实现 |
| Web 依赖 | `@sqlite.org/sqlite-wasm` | `idb` |

## 2. 代码结构

| 文件 | 职责 |
|---|---|
| `packages/core/src/storage.ts` | `Storage` / `Collection` 接口、`MemoryStorage`、集合与主键清单 |
| `packages/core/src/repository.ts` | 共享业务逻辑：周视图、放假调休判定与写入、展开输入组装 |
| `packages/core/src/sqlite-storage.ts` | SQLite 实现（Windows / Android / Node 测试） |
| `packages/core/src/sync.ts` | 同步框架：变更收集、远端应用、冲突记录、`MemoryRemote` |
| `apps/web/src/db/idb-storage.ts` | IndexedDB 实现 |
| `packages/core/src/schema/001_init.sql` | 仅 SQLite 端的物理结构 |

## 4. 体积变化（对应轻量化要求）

| 产物 | 变更前 gzip | 变更后 gzip |
|---|---|---|
| 应用 JS | 137 KB | 72.73 KB |
| SQLite wasm | 407 KB | 0（已移除） |

## 5. 新的已知限制

| # | 内容 |
|---|---|
| L9 | IndexedDB 无数据库约束：`CHECK`、外键、唯一索引只在 SQLite 端生效。同一份非法数据在 Web 端不会被拦截，校验责任落在共享数据访问层 |
| L10 | 同步的冲突解决当前为「远端版本更高则远端胜、同版本取更新时间较新者」，并记录冲突；字段级对比与用户选择属 M9 |
| L11 | `MemoryRemote` 仅用于本机验证，进程退出即丢失；服务端属下一期 |
