# 工作区文件权限修复记录（环境问题，与产品无关）

日期：2026-10-10
影响范围：本机工作目录 `E:\work\dsh\dawn-tick`
当前状态：**已修复并验证通过**

---

## 1. 发生了什么

会话开始时，连最普通的只读命令（列目录、`git status`）都直接失败：

```
Error: SetNamedSecurityInfoW failed (Win32 5): grantWrite(E:\work\dsh\dawn-tick)
```

含义：DSH 在给该工作目录授予写入权限时被 Windows 拒绝，导致**任何命令都无法执行**，
不只是不能写文件——连读都做不了。

## 2. 原因

`E:\work\dsh\dawn-tick` 这个文件夹缺少「修改所有者」这一项权限。
它从上一级 `E:\work\dsh` 继承到的权限里没有这一项（`E:\` 盘根目录的权限里也没有，
而盘根目录的所有者是系统而非当前用户，所以无法从更上层补齐）。

换句话说：**不是你的操作有问题，是这个文件夹自己的权限不完整。**

## 3. 做了什么修复

运行了 DSH 自带的诊断修复脚本，它做了一件事：

> 给 `E:\work\dsh\dawn-tick` 追加一条「当前登录用户完全控制」的权限项。

- 修改前已自动备份原权限，备份文件在 `E:\work\dsh\acl-recovery\`；
- 脚本改为**只**加这一条，没有删除任何其他权限、没有改动所有者、**没有改动任何文件内容**；
- 修复后重新读取权限验证：写入与所有者权限均已具备（verified）。

修复后的复查结论：

```
PATH=E:\work\dsh\dawn-tick
  OBJECT=E:\work\dsh\dawn-tick READABLE=True
    OWNER=当前用户  WRITE_DAC=True  WRITE_OWNER=True   ← 修复前为 False
GRANTED E:\work\dsh\dawn-tick
VERDICT=PRECONDITION → 已授予 → 验证通过
RECAP ... "verifications":[{"operation":"grant","status":"verified"}]
```

修复后重复执行原先失败的只读命令，**成功**（可正常列目录、执行 git）。

原权限可以完整还原，命令如下（需要时直接执行）：

