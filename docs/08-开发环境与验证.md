## 3.1 本地开发与本地打包

| 命令 | 作用 |
|---|---|
| `pnpm -C apps/web dev --host 127.0.0.1` | 启动 Web 开发服务器；注意默认只绑 `localhost`，探测请用 `localhost` 或显式 `--host` |
| `pnpm ui:smoke` | 界面冒烟测试 |
| `pnpm -C apps/desktop exec tauri build` | Windows 本地打包（exe 与 NSIS 安装包） |
| `pnpm -C apps/mobile exec cap sync android` + `sh ./gradlew assembleDebug` | Android 本地打包 |

教务抓取在三端各自的 HTTP 通道：Windows 走 `tauri-plugin-http`，Android 走 `CapacitorHttp`，Web 生产构建受同源策略限制。
本地开发时 Web 端由 Vite 中间件 `POST /__dev/http` 在开发服务器侧转发（仅 `serve` 阶段存在），因此浏览器里也能导入教务课表。

打包产物只留在本地：`apps/web/dist`、`apps/desktop/src-tauri/target/release`、`apps/mobile/android/app/build/outputs/apk`、`out-local`。

## 4. 验证

`powershell -File tools/verify/verify-all.ps1` 逐项输出 `[PASS] / [FAIL] / [SKIP]`，任一 FAIL 退出码为 1。

| 项 | 覆盖 |
|---|---|
| core 测试 | 数据模型、展开、同步、校验、导入导出、提醒、备份 |
| web 测试 | IndexedDB 存储、界面数据流、小组件快照、提醒链路 |
| 类型检查 | 工作区全部 TypeScript |
| 数据模型校验 | `001_init.sql` 约束在 Python SQLite 上逐条复验 |
| 设计令牌与无障碍 | 对比度（正文 ≥ 4.5:1、轮廓 ≥ 3:1、课程块内文字 ≥ 4.5:1）、触控 ≥ 44px、CSS 与令牌一致性 |
| Web 界面 | 双入口构建；组件库与页面（课表/今日/日程/导入/设置）随构建产物一并验证 |
| 界面冒烟 | jsdom 渲染 `App`：空库引导页、课表渲染课程与周次、当前时间指示线、切日程页、切设置页、搜索弹窗 |
| Web 构建 | `index.html` 与 `mini.html` 双入口 |
| Windows 产物 | 独立 exe 与 NSIS 安装包 |
| Android 产物 | APK 内的小组件类、清单声明与前端资源 |
| Rust 壳 | `cargo check --all-targets` 与 DDL 测试 |

发布侧另有自测：`node --test tools/release/plan.test.mjs tools/release/ci-gate.test.mjs`，覆盖渠道与标签计算、以及 CI 闸门的判定与轮询。

## 6. 环境坑

| 现象 | 处理 |
|---|---|
| MSVC 14.51 编译 `libsqlite3-sys` 报 `cl.exe D8050` | Cargo 配置 `[profile.dev] debug = 0` 与 `[profile.test] debug = 0` |
| Gradle 发行包下载 0 字节 | 改走腾讯镜像并提高 `networkTimeout` |
| 插件要求 `languageVersion=21` 而本机只有 17 | 免安装 Microsoft OpenJDK 21 并登记 `org.gradle.java.installations.paths` |
| `.kt` 文件被静默忽略 | app 模块应用 `org.jetbrains.kotlin.android` 插件 |
| Kotlin 与 Java 目标不一致 | `jvmTarget` 对齐 Capacitor 生成的 Java 21 |
| Linux 上 `./gradlew` 报 Permission denied | 增加 Git 可执行位，并以 `sh ./gradlew` 调用 |
| PowerShell 5.1 读取 UTF-8 脚本乱码 | 脚本保存为带 BOM 的 UTF-8 |
| `services.gradle.org`、`github.com` 直连超时 | 分别改用腾讯镜像与 `ghproxy.net` |
| 桌面端整页无法滚动 | 紧凑条样式写成 `html, body.mini-body { overflow: hidden }`，命中了主窗口的 `html`；已改为只作用于 `body.mini-body`，主窗口用 `h-dvh` + 内部滚动 |
| 便携版非管理员运行直接退出 | 紧凑条窗口改为托盘按需创建（启动时创建失败会终止进程）；托盘失败不再阻断启动；panic 与启动错误写入 `%LOCALAPPDATA%\com.dawntick.app\startup.log` |
| 正方公钥报「非法十六进制」 | 部分部署返回 Base64 模数，改为兼容十六进制、Base64 与前缀写法 |
| 正方登录报「密码错误」 | 参考实现输出的是十六进制字符串的 ASCII 再 Base64；改为先按该格式提交，被拒后自动换另一种编码重试一次 |
| 各端教务登录报 Failed to fetch | WebView 内 fetch 仍受同源策略限制；Windows 改走 `tauri-plugin-http`，Android 启用 `CapacitorHttp`，Web 保留提示 |
| PowerShell 重写 UTF-8 文件导致中文乱码 | 不要用 `Get-Content -Raw` + `Set-Content` 处理含中文的文件，改用编辑工具 |
| 非管理员启动「没反应」 | 三层原因：`tauri-plugin-http` 的 cookies 特性在启动时独占打开 `.cookies`（已有实例在托盘时失败，os error 5）；WebView2 用户数据目录同一时刻只能一个进程使用（`0x800700AA`）；目录若由提权进程创建则普通权限不可写。已关闭 cookies 特性、加入单实例、并在启动前检测可写性：优先改用「程序所在目录\DawnTick-data」，其次「%APPDATA%\com.dawntick.app」，同时把占用进程写入日志与提示框 |
| WebView2 数据目录双层 | WebView2 会在给定目录下自行创建 `EBWebView` 子目录，因此指定 `DawnTick-data` 后实际落在 `DawnTick-data\EBWebView` |
| 查看 WebView2 目录占用者 | `Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'" \| Select ProcessId,ParentProcessId,CommandLine`，按命令行中的 `--user-data-dir` 是否含 `com.dawntick.app` 判断归属 |
| 启动失败无任何提示 | Tauri 在创建 webview 失败时自行 panic，命令行看不到；已加 panic 钩子写日志并弹系统提示框 |
| 沙箱内无法验证 GUI 启动 | DSH 沙箱给子进程受限令牌，`%LOCALAPPDATA%` 下不可写；可用 `WEBVIEW2_USER_DATA_FOLDER` 指向工作区内目录验证启动 |
