# 02 数据与存储

建表 SQL 的唯一来源是 `packages/core/src/schema/001_init.sql` 与其后的编号迁移。

## 1. 数据表清单

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `users` | 使用者 | `id`、`nickname`（默认「我」） |
| `semesters` | 学期 | `user_id`、`start_date`、`total_weeks`（1–30）、`time_zone`、`is_active` |
| `time_slots` | 节次起止 | `semester_id`、`period_no`（1–40）、`start_time`、`end_time`、`label`、`section` |
| `courses` | 课程 | `semester_id`、`name`、`short_name`、`teacher`、`location`、`color`、`credits`、`note` |
| `course_schedules` | 排课 | `course_id`、`day_of_week`（1–7）、`period_start` / `period_end`、`weeks_mask`、`weeks_raw`、`room`、`start_time` / `end_time` |
| `events` | 条目 | `user_id`、`semester_id`、`type`、`title`、`on_date`、`start_at` / `end_at` / `due_at`、`parent_id` |
| `reminders` | 提醒 | `target_type`、`target_id`、`advance_minutes`、`enabled`、`skip_holidays`、`dnd`、`snooze_minutes` |
| `app_meta` | 键值元数据 | `key`、`value` |

公共列（`app_meta` 除外）：`id`（TEXT 主键，UUIDv7）、`created_at`、`updated_at`、`deleted_at`、`rev`、`dirty`。

### 1.1 条目类型

| `type` | 含义 | 关键字段 |
|---|---|---|
| `exam` | 考试 | `subject`、`seat_no`、`location`、`start_at` |
| `todo` | 待办 | `priority`（1–3）、`due_at`、`done`、`parent_id` |
| `homework` | 作业 | `due_at`、`subject` |
| `lab` | 实验 | `on_date`、`period_start` / `period_end`、`weeks_mask`、`nature` |
| `temp` | 临时日程 | `start_at`、`end_at`、`all_day` |
| `reschedule` | 调课 | `ref_schedule_id`、`action`、`on_date`、`new_date`、`new_period_start` / `new_period_end`、`new_room` |
| `holiday` | 放假 | `on_date`、`source` |
| `makeup` | 调休补课 | `on_date`、`as_day_of_week`、`source` |
| `workday` | 明确上课日 | `on_date`、`source` |

| 项 | 规则 |
|---|---|
| `action` | `move` / `cancel` / `room_change` / `add`；`move` 必须给 `new_date` |
| 逐条开关 | `countdown`、`manual_done`、`show_in_timetable`，取值 0 / 1 |
| 节假日来源优先级 | `manual` > `from_school` > `builtin` |
| 同日唯一 | 同一学期同一天只允许一条 `holiday` / `makeup` / `workday`（唯一索引 `ux_events_day_kind`） |
| 当前学期唯一 | 每用户只允许一条 `is_active = 1`（唯一索引 `ux_semesters_active`） |
| 节次唯一 | 同一学期内 `period_no` 不重复（唯一索引 `ux_time_slots`） |

### 1.2 `app_meta` 键

| 键 | 内容 |
|---|---|
| `schema_version` | 已应用的最后一个迁移 id |
| `device_id`、`sync_cursor` | 设备标识与同步游标，不参与备份 |
| `time_zone`、`auto_time_zone` | 显示时区与是否跟随设备时区 |
| `view_days`、`theme`、`theme_preset`、`motion` | 周视图天数、深浅模式、配色、动效 |
| `wal_mode` | 数据库日志模式，开库前先读 |
| `backup:<毫秒时间戳>` | Web 与 Android 的库内 JSON 快照 |
| `window_geometry` | Windows 窗口几何，窗口显示前读出应用 |

## 2. 时间口径

| 数据 | 存储形式 |
|---|---|
| 时刻：考试起止、截止、提醒触发、`created_at`、`updated_at` | INTEGER，UTC epoch 毫秒 |
| 日期：开学日期、假期日、调课原上课日、调课新日期 | TEXT，`YYYY-MM-DD`，不存时区 |
| 课表墙上时间：节次起止、`events.start_time` / `end_time`、`course_schedules.start_time` / `end_time` | TEXT，`HH:MM`，配合 `semesters.time_zone` 解释 |
| 周次与节次编号 | INTEGER，1 起算 |

| 项 | 规则 |
|---|---|
| 周次位图 | `weeks_mask` 第 N 周对应第 N−1 位；查询条件 `(weeks_mask >> (:week - 1)) & 1 = 1` |
| 日期与时刻的关系 | 日期不做时区换算；墙上时间加 `semesters.time_zone` 才得到 UTC 毫秒 |
| 显示时区取值顺序 | `auto_time_zone = '1'` 时用设备时区，否则用 `time_zone`，都非法时回退 `Asia/Shanghai` |
| 时区落库 | 学期行默认 `Asia/Shanghai`，设置项默认同为上海 |
| 周次起算 | 第 1 周为开学日期所在那一周，周一起算 |

## 3. 三端存储实现

| 端 | 实现 | 位置 |
|---|---|---|
| Web | IndexedDB，`idb` 封装，库名 `dawn-tick` | `apps/web/src/db/idb-storage.ts` |
| Windows | SQLite，Tauri 2 + `tauri-plugin-sql`，文件 `dawn-tick.db` | `apps/web/src/db/tauri-driver.ts` |
| Android | SQLite，`@capacitor-community/sqlite`，库名 `dawn_tick` | `apps/web/src/db/capacitor-driver.ts` |
| 测试与脚本 | `MemoryStorage`、`sqliteStorage`（`node:sqlite`） | `packages/core/src/storage.ts` |

| 项 | 规则 |
|---|---|
| 统一接口 | `Storage` 提供 `collection` / `readMeta` / `writeMeta` / `close`；`Collection` 提供 `get` / `getAll` / `put` / `putMany` / `delete` / `clear` |
| 集合与主键 | 由 `STORE_NAMES` / `STORE_KEYS` 单点定义，各端据此建存储 |
| 主键 | SQLite 端与 IndexedDB 端同名同主键；`app_meta` 主键为 `key`，其余为 `id` |
| 外键 | SQLite 端每次建立连接执行 `PRAGMA foreign_keys = ON` |
| 约束差异 | `CHECK`、外键、唯一索引只在 SQLite 端生效；Web 端靠共享数据访问层校验 |
| 业务访问方式 | 业务代码只经 `Storage` 访问数据，不直接接触具体驱动 |

## 4. 迁移机制

| 迁移 | 作用 |
|---|---|
| `001_init` | 建 8 张表、索引与唯一索引；`app_meta` 建为键值表 |
| `002_event_kinds` | 事件表扩充为 9 种 `type`，新增逐条开关与 `nature`、实验节次与周次位图列；带 `CHECK` 的表按「改名 → 建新表 → 拷数据 → 删旧表」重建 |
| `003_custom_time` | 给 `events` 与 `course_schedules` 各加 `start_time` / `end_time` 两个可空列 |
| `004_timetable_entries` | 加 `show_in_timetable`（默认 0），把 `type = 'lab'` 的既有行回填为 1 |
| `005_due_at_any` | 放开 `due_at`，所有条目类型都能带截止时刻；重建事件表 |
| `006_schema_version` | 建 `app_meta` 并把 `schema_version` 写成 `006_schema_version`，统一三端版本口径 |

| 项 | 规则 |
|---|---|
| 应用方式 | 按 id 升序应用尚未执行的迁移，逐条把 id 写入 `app_meta.schema_version` |
| Windows 侧 | 由 `tauri-plugin-sql` 按版本号应用迁移 |
| Web 与 Android 侧 | 每次启动调用 `migrate`，已应用的跳过 |
| 历史文件 | 已发布的迁移文件不得再修改；新增结构一律追加新迁移 |

## 5. 存储位置与日志模式

| 端 | 数据位置 |
|---|---|
| Windows 安装版 | `%APPDATA%\com.dawntick.app` |
| Windows 便携版 | 程序所在目录 |
| Windows 自定义位置 | 设置页「数据」填写，留空用默认，改完重启生效 |
| Windows 回退顺序 | 默认位置不可写时依次回退 `%LOCALAPPDATA%\com.dawntick.app`、`%TEMP%\DawnTick` |
| Android / Web | 各自的应用私有目录，不提供修改入口 |
| WebView2 用户数据 | 固定 `%LOCALAPPDATA%\com.dawntick.app\EBWebView` |
| 数据目录内容 | 数据库与日志；窗口几何存在 `app_meta.window_geometry` |

| 日志模式 | 行为 |
|---|---|
| `auto` | 按存储位置判定：便携版关闭，安装版与 Android 开启 |
| `on` | `journal_mode=WAL`，产生 `-wal` / `-shm` 附带文件 |
| `off` | `journal_mode=DELETE`，数据库保持单个文件 |
| Web | 使用 IndexedDB，没有日志模式可设 |
| 日志文件 | `dawn-tick.log`，行为 `YYYY-MM-DD HH:MM:SS.mmm ±HH:MM [level] scope: 消息` |
| 日志级别 | error / warn / info / debug / trace，dev 渠道默认 trace，其余默认 info |

## 6. 备份与恢复

| 端 | 快照实现 |
|---|---|
| Windows | `VACUUM INTO` 把整库写进数据目录 `backups/`，文件名带时间戳 |
| Web 与 Android | 把 JSON 快照写进库内 `app_meta`，键为 `backup:<毫秒时间戳>` |

| 项 | 规则 |
|---|---|
| 自动备份 | 总开关 + 「启动时」+「每天」两个开关；启动那次同一分钟内不重复做 |
| 保留份数 | 默认 10，可设 1–100，超出删最旧 |
| 手动备份 | 设置页可手动做一份快照 |
| 恢复 | 文件快照写一条恢复请求到 `pending-restore.json`，重启时在打开数据库之前覆盖当前库 |
| 恢复前 | 设置页恢复前先做一份当前库的快照 |
| 恢复请求 | 排队、套用与忽略的结论都写进日志 |
| 库内快照恢复 | Web 与 Android 的 JSON 快照当场清空所选模块后覆盖，不需要重启 |
| 0 字节快照 | `VACUUM INTO` 失败留下的 0 字节文件会被清理，且不作为恢复来源 |
| 启动自检 | Windows 在打开数据库之前跑一次 `quick_check` |
| 损坏处置 | 自检判定损坏时把损坏文件留存为 `dawn-tick.db.corrupt-<时间>` |
| 恢复来源 | 用最近一份通过自检的快照恢复；没有可用快照则保持无库并新建空库 |
| 结论去向 | 自检结论写进日志并在界面提示 |
| Web 与 Android | 不做启动自检；打开数据库报损坏时提示从备份导入恢复 |

## 7. 导出导入

| 格式 | 内容 |
|---|---|
| JSON 文件 | 备份对象，`format` 为 `dawn-tick-backup`，`version` 为 1 |
| Base64 文本 | 同一份 JSON 的 Base64，可在界面文本框粘贴 |
| 整包 zip | 包内 `backup.json`；可选加 `presets/snapshot.json`、`presets/content.json` 与日志 |

| 项 | 规则 |
|---|---|
| 模块 | 学期与节次、课程与排课、日程与待办、提醒、设置 |
| 设置范围 | 导出白名单内的设置键；`device_id`、`sync_cursor` 与 WebDAV 密码不进导出 |
| 导入入口 | 一个「导入配置」，可选文件也可粘贴文本；`.zip` 取包内 `backup.json` |
| 冲突策略 | `skip` 跳过已有数据、`overwrite` 覆盖已有数据、`clear` 清空所选模块后导入、`merge` 按修改时间合并 |
| 逐行校验 | 导入前逐行校验，非法行计入跳过并给出警告，不中断整体导入 |
| 写入标记 | 导入的行置 `dirty = 1`，`updated_at` 取导入时刻 |
| 版本校验 | 备份版本高于当前支持的版本时拒绝导入 |

## 8. WebDAV 同步范围

| 项 | 内容 |
|---|---|
| 上传内容 | 整库快照、设置与预设打成一个 zip |
| 远端命名 | 固定名 `DawnTick-backup.zip` 覆盖；开「远端保留历史多份」时用带时间戳的文件名 |
| 手动操作 | 可手动上传与下载 |
| 自动同步 | 总开关 + 「启动时」+「每天」两个开关 |
| 判定顺序 | 先比远端 `Last-Modified` 与上次上传时间；远端更新则提示下载，否则上传 |
| 下载选项 | 下载前自动备份本机，可选「恢复全部」或「只应用设置与预设」 |
| 方向 | 只上传，不自动下载 |
| 凭据存放 | 地址、用户名与密码存在本机设置里，密码不参与导出 |
