# 晓刻 — 数据模型设计（v3 定稿）

> 状态：**v3 定稿** — 已纳入负责人 2026-10-10 全部决策；剩余少量 ⚠ 仅属细节，不影响建库。
> 本文件所有 DDL 均在真实 SQLite 上实测通过（见 `records/M0-数据模型校验记录.md`）。
> v1 → v2 → v3 的变化见第 8 节。

---

## 1. 设计前提

| 前提 | 来源 |
|---|---|
| 本地 SQLite 是唯一真相来源（本期无服务端） | 架构原则、D3 |
| 单机单用户，不做登录 | D5 |
| **三端统一 Web 栈**（Web / Windows=Tauri 2 / Android=Capacitor） | D25 |
| **本期就建好同步预留字段**（`rev` / `dirty`），下一期接同步不改表 | D29 |
| **轻量化**：不引重量级依赖，架构从简 | D30 |

### 1.1 通用约定

| 约定 | 取值 | 状态 |
|---|---|---|
| 主键 | `id TEXT PRIMARY KEY`，**UUIDv7**（时间有序、跨设备不冲突） | ✅ D19 |
| 时间戳 | `created_at` / `updated_at`：INTEGER，Unix 毫秒（UTC） | ✅ |
| 同步预留 | `rev INTEGER NOT NULL DEFAULT 0`、`dirty INTEGER NOT NULL DEFAULT 0` | ✅ D29 |
| 业务日期 | `TEXT`，`YYYY-MM-DD`（本地墙钟） | ✅ |
| 业务时刻 | `TEXT`，`YYYY-MM-DDTHH:MM:SS+08:00`（本地墙钟 + 时区） | ✅ |
| 软删除 | `deleted_at INTEGER NULL`，查询一律过滤 | ✅ |
| 布尔值 | INTEGER 0/1 | ✅ |
| 枚举 | TEXT + `CHECK(...)` | ✅ |
| 外键 | `PRAGMA foreign_keys = ON` | ✅ |
| 周次起算 | **第 N 周 ↔ 位图第 (N-1) 位**，全项目统一 1 起算 | ✅ 风险 R1/R7 |

**同步字段语义（为下一期预留，本期只写 0）**：
`rev` = 本行被修改的次数，同步时用于检测冲突；`dirty` = 有本地改动待推送。
本期不对它们做任何逻辑处理，但所有写操作都走统一的数据访问层，将来只需改这一层。

```sql
CREATE TABLE users (
  id          TEXT PRIMARY KEY,
  nickname    TEXT NOT NULL DEFAULT '我',
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,
  rev         INTEGER NOT NULL DEFAULT 0,
  dirty       INTEGER NOT NULL DEFAULT 0

```

### 2.2 `semesters` 学期
✅ **「起始日期 + 总周数」** 定义学期（D9）。

```sql
CREATE TABLE semesters (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  start_date  TEXT NOT NULL,                 -- 第 1 周的周一 'YYYY-MM-DD'
  total_weeks INTEGER NOT NULL DEFAULT 20 CHECK (total_weeks BETWEEN 1 AND 30),
  is_active   INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,
  rev         INTEGER NOT NULL DEFAULT 0,
  dirty       INTEGER NOT NULL DEFAULT 0
);

CREATE UNIQUE INDEX ux_semesters_active
  ON semesters(user_id) WHERE is_active = 1 AND deleted_at IS NULL;
```

⚠ 细节待定：`start_date` 我按**第 1 周周一**实现（若教务给「开学第一天」需换算）。

### 2.3 `time_slots` 节次时间
✅ **节次数与时间可自定义 + 导入时自动识别节次时间**（D21）。

```sql
CREATE TABLE time_slots (
  id          TEXT PRIMARY KEY,
  semester_id TEXT NOT NULL REFERENCES semesters(id) ON DELETE CASCADE,
  period_no   INTEGER NOT NULL CHECK (period_no BETWEEN 1 AND 40),
  start_time  TEXT NOT NULL,
  end_time    TEXT NOT NULL,
  label       TEXT,
  section     TEXT CHECK (section IN ('am','pm','night')),
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,
  rev         INTEGER NOT NULL DEFAULT 0,
  dirty       INTEGER NOT NULL DEFAULT 0
);

CREATE UNIQUE INDEX ux_time_slots ON time_slots(semester_id, period_no)
  WHERE deleted_at IS NULL;
CREATE INDEX ix_time_slots_semester ON time_slots(semester_id);
```

**一天几节由本表行数决定**，不写死在代码里；`CHECK 1..40` 只是防脏数据的粗上界。

⚠ 细节待定：`section`（上午/下午/晚上）是手动设置还是按时间自动推断（我倾向自动推断 + 允许覆盖）。

### 2.4 `courses` 课程
✅ 加**学分**与**备注/短名**（D13）；颜色存**十六进制**（D14）。

```sql
CREATE TABLE courses (
  id          TEXT PRIMARY KEY,
  semester_id TEXT NOT NULL REFERENCES semesters(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  short_name  TEXT,                          -- '高数'，课表格子空间小
  teacher     TEXT,
  location    TEXT,                          -- 默认地点，可被排课行覆盖
  color       TEXT NOT NULL DEFAULT '#4F8DFD',
  credits     REAL CHECK (credits IS NULL OR credits >= 0),
  note        TEXT,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL,
  deleted_at  INTEGER,
  rev         INTEGER NOT NULL DEFAULT 0,
  dirty       INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX ix_courses_semester ON courses(semester_id);
```

### 2.5 `course_schedules` 排课
✅ 周次 = **周次集合**（D9），存储编码 = **位图整数**（D20）。

```sql
CREATE TABLE course_schedules (
  id            TEXT PRIMARY KEY,
  course_id     TEXT NOT NULL REFERENCES courses(id) ON DELETE CASCADE,
  day_of_week   INTEGER NOT NULL CHECK (day_of_week BETWEEN 1 AND 7),
  period_start  INTEGER NOT NULL CHECK (period_start BETWEEN 1 AND 40),
  period_end    INTEGER NOT NULL CHECK (period_end   BETWEEN 1 AND 40),
  weeks_mask    INTEGER NOT NULL CHECK (weeks_mask > 0),  -- 第 N 周 = 第 (N-1) 位
  weeks_raw     TEXT,                        -- 教务原文，如 '1-16周(单)'，用于显示与回导
  room          TEXT,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  deleted_at    INTEGER,
  rev           INTEGER NOT NULL DEFAULT 0,
  dirty         INTEGER NOT NULL DEFAULT 0,
  CHECK (period_end >= period_start)
);

CREATE INDEX ix_schedules_course ON course_schedules(course_id);
CREATE INDEX ix_schedules_day    ON course_schedules(day_of_week);
```

**位图语义**（已实测）：

| 周次集合 | `weeks_mask` |
|---|---|
| 第 1–16 周 | `65535` |
| 双周 2–16 | `43690` |
| 仅 1/3/5/7 周 | `85` |

查询：`(weeks_mask >> (:week - 1)) & 1 = 1`

**为什么用位图**：不依赖 SQLite 的 JSON 函数。Android 系统自带 SQLite 的版本与编译选项不一致，
`json_each` 不能假设可用；位图在任何 SQLite 上都能跑，且索引友好。

**实现要求（防错）**：位运算必须封装成一对函数再使用，禁止散落裸写：

```
set_week(mask, week) -> mask | (1 << (week - 1))
has_week(mask, week) -> (mask >> (week - 1)) & 1 == 1
```

### 2.6 `reminders` 提醒

  updated_at      INTEGER NOT NULL,
  deleted_at      INTEGER,
  rev             INTEGER NOT NULL DEFAULT 0,
  dirty           INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX ix_reminders_target ON reminders(target_type, target_id);

### 2.7 `events` 日程（单表承载 7 种语义）
✅ 调课、调休、节假日**全部并入本表，不新建表**（D10）。

```sql
CREATE TABLE events (
  id               TEXT PRIMARY KEY,
  user_id          TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  semester_id      TEXT REFERENCES semesters(id) ON DELETE SET NULL,
  type             TEXT NOT NULL CHECK (type IN (
                     'exam',        -- 考试
                     'todo',        -- 待办
                     'temp',        -- 临时日程
                     'reschedule',  -- 调课
                     'holiday',     -- 放假（当天不排课）
                     'makeup',      -- 调休补课（当天按某星期上课）
                     'workday'      -- 明确为上课日（覆盖内置节假日）
                   )),
  title            TEXT NOT NULL,
  on_date          TEXT,      -- 针对日期：假期日 / 补课日 / 被调课的原上课日
  start_at         TEXT,
  end_at           TEXT,
  all_day          INTEGER NOT NULL DEFAULT 0,
  location         TEXT,
  note             TEXT,
  done             INTEGER NOT NULL DEFAULT 0,
  -- 调课专用
  ref_schedule_id  TEXT REFERENCES course_schedules(id) ON DELETE CASCADE,
  action           TEXT CHECK (action IN ('move','cancel','room_change','add')),
  new_date         TEXT,
  new_period_start INTEGER CHECK (new_period_start BETWEEN 1 AND 40),
  new_period_end   INTEGER CHECK (new_period_end   BETWEEN 1 AND 40),
  new_room         TEXT,
  -- 调休 / 节假日专用
  as_day_of_week   INTEGER CHECK (as_day_of_week BETWEEN 1 AND 7),
  source           TEXT CHECK (source IN ('builtin','manual','from_school')),
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL,
  deleted_at       INTEGER,
  rev              INTEGER NOT NULL DEFAULT 0,
  dirty            INTEGER NOT NULL DEFAULT 0,

  CHECK (type <> 'reschedule' OR (ref_schedule_id IS NOT NULL AND action IS NOT NULL)),
  CHECK (type <> 'reschedule' OR action <> 'move' OR new_date IS NOT NULL),
  CHECK (type NOT IN ('holiday','makeup','workday') OR on_date IS NOT NULL),
  CHECK (type <> 'makeup'      OR as_day_of_week IS NOT NULL),
  CHECK (type <> 'reschedule'  OR (new_period_end IS NULL OR new_period_start IS NOT NULL)),
  CHECK (new_period_end IS NULL OR new_period_start IS NULL OR new_period_end >= new_period_start)
);

CREATE INDEX ix_events_user_time ON events(user_id, start_at);
CREATE INDEX ix_events_semester  ON events(semester_id);
CREATE INDEX ix_events_type_date ON events(type, on_date);
CREATE UNIQUE INDEX ux_events_day_kind
  ON events(semester_id, on_date)
  WHERE type IN ('holiday','makeup','workday') AND deleted_at IS NULL;
```

**节假日来源与优先级** ✅ D12 + D22：

| 优先级 | `source` 取值 | 说明 |
|---|---|---|
| 1（最高） | `manual` | 用户手动改动，覆盖一切 |
| 2 | `from_school` | 教务校历（各校调休安排不同，比全国表更贴切） |
| 3 | `builtin` | 内置中国法定节假日，兜底 |

**实现方式（已实测，重要）**：数据库层面**每个（学期, 日期）只允许一条**放假/调休/上课日记录（部分唯一索引强制）。
所以优先级**不是「查询时在多行里挑」，而是「写入/导入时的覆盖决策」**：

| 情形 | 动作 |
|---|---|
| 该日期无记录 | 直接插入 |
| 已有记录，新来源优先级**更高** | 覆盖（UPDATE），例如教务校历覆盖内置 |
| 已有记录，新来源优先级**更低或相同** | 跳过，保留原记录，例如内置不得覆盖手动 |

已实测两条关键路径：**教务校历覆盖内置 ✅**、**内置不得覆盖手动 ✅**，且每天始终只有一条记录。
**UI 需显示当前生效来源**，让用户知道某天的判定到底来自哪里。

#### ⚠ 我必须如实告知的代价（D10 的直接后果）

| 代价 | 缓解 |
|---|---|
| 表宽 24 列，多数行只用一半 | 6 项条件 `CHECK` 按 type 强制必填（已实测生效） |
| 语义靠 `type` 区分，漏写条件会串数据 | 所有查询封装在数据访问层，禁止业务代码裸拼 SQL |
| 唯一性约束复杂 | 用部分唯一索引（已实测） |
| 将来扩展变难 | 记入风险 R9；若将来难维护，拆表是纯迁移，数据可完整搬迁 |

⚠ 细节待定：`todo` 是否需要优先级/截止提醒/子任务；`exam` 是否需要科目/考场/座位号。

## 4. 关键查询

```sql
-- Q1. 第 N 周某天的课（周视图）
SELECT c.name, c.short_name, c.color, cs.period_start, cs.period_end,
       COALESCE(cs.room, c.location) AS room
FROM course_schedules cs
JOIN courses c ON c.id = cs.course_id
WHERE c.semester_id = :sid
  AND cs.day_of_week = :dow
  AND (cs.weeks_mask >> (:week - 1)) & 1 = 1
  AND cs.deleted_at IS NULL AND c.deleted_at IS NULL
ORDER BY cs.period_start;

-- Q2. 某天的放假/调休（提醒是否跳过 + 周视图覆盖），按 D22 优先级取最优先来源
SELECT type, as_day_of_week, source FROM events
WHERE semester_id = :sid AND on_date = :date
  AND type IN ('holiday','makeup','workday') AND deleted_at IS NULL
ORDER BY CASE source WHEN 'manual' THEN 1 WHEN 'from_school' THEN 2 ELSE 3 END
LIMIT 1;

-- Q3. 某次课的调课覆盖
SELECT action, new_date, new_period_start, new_period_end, new_room FROM events
WHERE type = 'reschedule' AND ref_schedule_id = :schedule_id
  AND on_date = :original_date AND deleted_at IS NULL;
```

## 5. 架构要求：一套 DDL，三种 SQLite 驱动

三端统一 Web 栈（D25）意味着**同一份数据模型要跑在三个不同的 SQLite 载体上**：

| 端 | SQLite 载体 | 备注 |
|---|---|---|
| Web | SQLite-WASM + OPFS | 浏览器内真跑 SQLite（D25）；需跨源隔离响应头 |
| Windows | Tauri 2 + `tauri-plugin-sql`（sqlx） | 插件自带迁移 API |
| Android | Capacitor + `@capacitor-community/sqlite` | 迁移需自行应用 |

**硬性约束（写进代码规范）**：

1. **建表 SQL 只用标准 SQLite 语法**：不用 `json_each`、不用 FTS（除非确认三端都可用）、
   不用 SQLite 方言扩展。当前模型已满足（位图用纯位运算）。
2. **迁移脚本是一份共享的 SQL 列表**（`001_init.sql`, `002_...`），由**各端的 applier** 分别执行；
   迁移版本号记在 `app_meta.schema_version`。
3. **业务代码不得直连数据库**：统一走一个 TypeScript 数据访问层，屏蔽三端驱动差异；
   这是「一套 DDL 三端跑」能成立的唯一保障，也是 `rev`/`dirty` 将来只改一处的前提。
4. **`PRAGMA foreign_keys = ON` 必须在每次连接建立时执行**（三端都要显式做）。

⚠ 细节待定：数据访问层是否引入 ORM（如 Drizzle/Kysely）还是纯手写 SQL？
纯手写更轻（符合 D30 轻量化），但迁移与类型安全要自己保证。**我倾向纯手写 + 类型定义**。

## 6. 「展开(expand)」函数——本项目最复杂的一段逻辑

`course_schedules` 里没有绝对时刻，必须结合 `semesters.start_date` + `time_slots` 计算：

```
expand(semester, date_range) -> [occurrence]
occurrence = { 日期, 第几节, 起止墙钟时间, 课程, 教室, 是否被调课/取消 }
```

**必须在这一层统一叠加**（`events` 表的覆盖规则），保证三处结果完全一致：

| 覆盖 | 规则 |
|---|---|
| 放假（`holiday`） | 当天不排课 |
| 调休补课（`makeup`） | 当天按 `as_day_of_week` 指定的星期上课 |
| 明确上课日（`workday`） | 覆盖内置节假日判定 |
| 调课（`reschedule`） | `cancel` 取消该次；`move` 改期；`room_change` 只改教室 |
| 来源冲突 | 按 D22 优先级（手动 > 教务 > 内置）取最高 |

课表渲染、提醒调度、小组件三处**必须共用这一个函数**，否则必然出现「课表显示有课、提醒却没响」这类问题。

⚠ 细节待定：展开结果是否缓存落库？（我倾向**纯函数展开，不落库**，符合轻量化 D30）

## 7. 风险清单

| # | 风险 | 说明 |
|---|---|---|
| R1 | 1 起算 vs 0 起算 | 统一 1 起算；位图第 N 周 ↔ 第 (N-1) 位，最易错，须专门单测 |
| R2 | 时区与墙钟 | 业务时刻存**墙钟时间**，时间戳存 **UTC 毫秒**，绝不混用 |
| R3 | 软删除 + 唯一索引 | 已实测：部分唯一索引按预期放行 |
| R4 | `reminders.target_id` 无外键 | 删除课程/日程须在数据访问层清理提醒 |
| R5 | 提醒精确性依赖系统能力 | Android 精确闹钟权限；Windows 用**常驻托盘 + 开机自启**（D28）规避计划通知的 5 分钟投递窗口 |
| R6 | 四者叠加 | 周次集合 + 调休 + 调课 + 时间 → 必须用固定样例做单测 |
| R7 | 位图易错 | 封装 `set_week`/`has_week` 并单测，禁止裸写位运算 |
| R8 | 时间戳与墙钟混用 | 同 R2 |
| R9 | 单表 7 种语义的长期可维护性 | D10 所致；CHECK 约束 + 数据访问层封装；将来可纯迁移拆分 |
| R10 | 节假日三来源冲突 | 已定优先级（D22）；UI 必须显示生效来源 |
| R11 | **三端 SQLite 能力差异** | Web(WASM) / Tauri(sqlx) / Capacitor 的 SQLite 版本与编译选项不同；禁止使用非标准函数（见第 5 节） |
