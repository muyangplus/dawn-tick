# 07 发布与版本规范

## 0. 构建纪律

- 只用 `tools/build-local.ps1` 产出交付件；**不得**用 `cargo build` 的产物替代，也不得从 `target` 目录手工拷贝 exe 充当交付件。
- 直接 `cargo build` 的产物按开发模式编译，窗口会去加载 `devUrl`（`http://localhost:5173`），运行后表现为「localhost 拒绝连接」。
- 打包脚本会校验产物是否嵌入了前端哈希资源名，未嵌入则直接报错。

## 1. 渠道

| 渠道 | 来源分支 | 发布方式 | 标签 | Release 标记 | 构建类型 |
|---|---|---|---|---|---|
| dev | `dev` | 滚动覆盖，手动或定时触发 | 固定 `dev-latest` | 预发布 | debug（Windows `--debug`、Android `assembleDebug`） |
| beta | `beta`（从 dev 合并） | 按需手动触发，保留历史 | `vX.Y.Z-beta.<n>` | 预发布 | release |
| release | `main`（从 beta 合并） | 打标签触发，自动发布 | `vX.Y.Z` | 正式 Release | release |

三端均写入统一日志：启动与崩溃、教务登录全过程、数据读写与同步；日志不含明文密码与密文，可在设置页导出。

Windows 侧数据目录：安装版在 `%APPDATA%\com.dawntick.app`，便携版（可执行文件名为 `DawnTick.exe` 且不在 `%LOCALAPPDATA%\DawnTick` 下）在程序所在目录；数据库、窗口几何与日志都在该目录内，设置页「数据」可填自定义位置（留空用默认，相对路径相对程序目录），改完重启生效。数据库日志模式由「启用 WAL 日志模式」开关决定：默认便携版关闭（`journal_mode=DELETE`，数据库为单个文件）、安装版开启；关闭后不再产生 `-wal` / `-shm`。日志同时输出到控制台：从终端启动时输出到该终端，提权启动时先附加父控制台、无法附加则另开一个日志控制台；数据目录不可写时依次回退 `%LOCALAPPDATA%\com.dawntick.app` 与 `%TEMP%\DawnTick`。日志行为 `YYYY-MM-DD HH:MM:SS.mmm ±HH:MM [level] scope: 消息`，文件、控制台与「导出日志」同一格式。设置页的「打开数据目录」与「打开日志文件所在目录」在资源管理器中定位对应目录。

备份：Windows 用 `VACUUM INTO` 把整库写成 `backups/dawn-tick-<yyyyMMdd-HHmmss>.db`，Web 与 Android 把 JSON 快照写进库内；总开关加「启动时」「每天」两个开关，保留份数可设 1–100（默认 10），超出自动删最旧。设置页列快照可查看、恢复、删除；恢复文件快照时先在 `pending-restore.json` 排队，重启时在打开数据库之前覆盖，恢复前自动备一份当前库。跨设备迁移用设置页的导出导入：JSON 文件、Base64 文本或整包 zip（可选同时打包预设快照与日志），导入冲突处理为跳过 / 覆盖 / 清空所选模块后导入 / 按修改时间合并。

WebDAV 同步：把整库快照与设置预设打成一个 zip 放到远端目录，固定名 `DawnTick-backup.zip` 覆盖，也可按「远端保留历史多份」改成带时间戳的多份。地址填完整目录 URL，用户名与密码存在本机设置里（密码不参与导出）。自动同步分「启动时」与「每天」两个开关：先比远端 `Last-Modified` 与上次上传时间，远端更新就提示下载（下载前自动备份本机，可选「恢复全部」或「只应用设置与预设」），否则上传；只上传、不自动下载。Windows 用 Tauri 官方 http 插件发请求（不受 WebView 的 CORS 限制），Android 由 Capacitor 的原生 HTTP 接管 fetch，Web 走浏览器 fetch（需服务端允许跨域）。

第三方依赖的清单与许可证全文写在仓库根目录 `THIRD-PARTY-LICENSES.md`，由 `node tools/legal/collect-licenses.mjs` 从各端清单与已安装依赖的元数据生成；`--check` 校验磁盘内容与依赖一致，不一致退出码 1。应用内「关于」展示同一份清单。

桌面小组件在手机端设置页给出添加引导：每个尺寸一个「添加到桌面」按钮，走 Capacitor 插件 `DawnTickWidget.requestPin`（Android `requestPinAppWidget`）；系统版本低于 Android 8 或启动器不支持时返回 `supported=false` 并提示手动添加步骤。Windows 端只显示悬浮窗设置（`悬浮窗` 与 `悬浮窗样式`），手机端不显示这两项。

客户端检查更新按渠道读取 `api.github.com` 的发布接口（`dev-latest`、`beta-latest` 与最新正式版），失败时回退发布内的 `version.json`；预设更新先取 `raw.githubusercontent.com`，失败时回退 `api.github.com` 的 contents 接口。两条链路都不使用第三方镜像。设置页「更新与维护」展示检查结果、预设版本与运行权限；「自动检查版本更新」默认开启，启动后自动查一次，发现新版本时弹窗显示版本、渠道与发布说明。

渠道提示：dev 与 beta 各自有一条首次提示（开发版可能频繁更新、测试版可能不稳定），已读记录写在 `app_meta.seen_notices`，按提示 id 记录——不是初次使用但没提示过这条信息也会弹。切到测试版后自动再检查一次更新。

`publish.yml` 的 dev 渠道在构建前比对 `dev-latest` 发布正文里的「提交 <sha>」与本次 `GITHUB_SHA`，相同则整个流水线跳过（`skip=true`，其余 job 带 `if: needs.plan.outputs.skip != 'true'`），定时任务不会重复构建没有新提交的版本。

### 1.1 渠道功能差异

| 功能 | 可见渠道 | 说明 |
|---|---|---|
| 日志导出与诊断信息 | dev、beta | 正式版隐藏入口，日志仍会写入本地文件 |

登记的唯一位置为 `apps/web/src/channel.ts` 的 `FEATURES`；构建时由 `DT_CHANNEL` 注入，本地与 CI 默认 `dev`，发布工作流按渠道注入。关于页显示版本与渠道。

### 1.2 数据库迁移

`packages/core/src/schema/` 下的迁移按 id 升序应用，各端一致：`001_init` 建表，`002_event_kinds` 扩充事件表（作业 / 实验类型与逐条开关，按「改名 → 建新表 → 拷数据 → 删旧表」重建），`003_custom_time` 为事件与排课加自定义时间列，`004_timetable_entries` 加「是否显示在课表上」并把实验回填为显示，`005_due_at_any` 放开截止时刻（所有条目类型都能带 `due_at`）。Windows 侧由 `tauri-plugin-sql` 按版本号应用，Web / Android 侧每次启动都调用 `migrate`（已应用的会跳过）。

已发布的迁移文件不得再修改：`tauri-plugin-sql` 记录已应用迁移的校验和，改动历史文件会让老库启动失败。新增结构一律追加新迁移。

## 3. 触发

| 事件 | 渠道 | 构建自 | 行为 |
|---|---|---|---|
| 打标签 `vX.Y.Z` | release | 该标签 | 创建正式 Release |
| 打标签 `vX.Y.Z-beta.N` | beta | 该标签 | 创建 beta 预发布 |
| 手动触发（选 dev） | dev | `dev` | 删除并重建 `dev-latest` |
| 手动触发（选 beta） | beta | `beta` | 标签续号 `vX.Y.Z-beta.<n>` |
| 手动触发（选 release） | release | `main` | 按当前版本号发布 |
| 定时（每天 UTC 01:00） | dev | `dev` | 同手动 dev |

push 到 `dev`、`beta`、`main` 不触发发版，只触发 CI。

发布前置：发版工作流先执行 `gate` 任务，按构建引用解析出提交，再轮询该提交上的 `ci.yml` 运行结果。成功才继续构建；失败或无记录（等待上限 40 分钟）则中止。CI 不重复运行：`ci.yml` 已监听 `v*` 标签，其并发键为「分支-提交号」，同一提交上只跑一次检查。

## 4. 产物

产物文件名使用 ASCII 与英文名 `DawnTick`：GitHub 会剥离 Release 产物名中的非 ASCII 字符（实测上传 `晓刻-测试.txt` 得到 `-.txt`），中文名保留在 Release 标题。每个产物配一个同名的 `.sha256` 文件，内容为裸 SHA256 值。

| 文件 | 来源 |
|---|---|
| `DawnTick-<version>-<channel>-windows-x64-setup.exe` | `tauri build` 的 NSIS 安装包 |
| `DawnTick-<version>-<channel>-windows-x64-portable.zip` | `tauri build` 的独立 exe，包内为 `DawnTick.exe` |
| `DawnTick-<version>-<channel>-android.apk` | dev 为 `assembleDebug`、其余渠道为 `assembleRelease`（都有签名材料时用同一把正式密钥） |
| `DawnTick-<version>-<channel>-web.zip` | `apps/web/dist` |
| `<产物文件名>.sha256` | 对应产物的 SHA256 |

dev 渠道的 `<version>` 带构建时间戳（`yyyyMMddHHmm`，本地时间），例如 `DawnTick-0.1.0.202510131430-dev-android.apk`；beta 与 release 保持 `X.Y.Z`。时间戳只用于区分构建，不参与版本比较（`compareVersions` 只比 `major.minor.patch`），所以本地 dev 构建不会因时间戳被判成「有新版本」。Android 的 versionCode 取 2024-01-01 起的分钟数，随时间单调递增，dev / beta / release 互相覆盖安装都不会被判成降级。

Android 的 dev 构建在提供签名材料时同样使用正式密钥签名：材料来自环境变量 `ANDROID_KEYSTORE_PATH` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`，本地也可写在 `apps/mobile/android/keystore.properties` 或 `<仓库根>/keys/keystore.properties`（两处都在 .gitignore 内，键名两种写法都认）。同一把密钥才能覆盖安装；若旧安装是调试密钥签的，需要先卸载一次。

仓库 secret 的配置（需要 `gh` 已登录且对该仓库有 secrets 写权限）：

```powershell
gh auth login
powershell -ExecutionPolicy Bypass -File tools/release/set-github-secrets.ps1
```

脚本从 `keys/keystore.properties` 取材料，写入 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 四个 secret，只打印 secret 名与字节数，不回显口令。`ANDROID_KEYSTORE_BASE64` 是密钥库文件的单行 base64（`[Convert]::ToBase64String([IO.File]::ReadAllBytes($jks))`），`publish.yml` 的 Android job 会把它解回 `$RUNNER_TEMP/release.key` 后交给 Gradle。

发布说明：自动生成，并按渠道指定比较基准。

| 渠道 | 比较基准 | 说明头部 |
|---|---|---|
| dev | 最近一个非 `dev-latest` 的发布 | `渠道 dev · 来源 dev · 提交 <sha>` |
| beta | 最近一个 `-beta.` 发布 | `渠道 beta · 来源 beta · 提交 <sha>` |
| release | 最近一个正式发布 | `渠道 release · 来源 main · 提交 <sha>` |

定时任务的执行细节：GitHub 的 `schedule` 只读取默认分支的工作流文件，因此定时任务实际用的是 `main` 上的 `publish.yml`；该任务会先检出 `dev`，使版本号与标签规则取自 `dev`。工作流结构本身的改动需合并到 `main` 才对定时任务生效。

## 6. 密钥

| GitHub Secret | 内容 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `keys/dawn-tick-release.key` 的 base64 |
| `ANDROID_KEYSTORE_PASSWORD` | 密钥库口令 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥口令 |

密钥库为 `.key` 后缀，放在仓库内 `keys/` 目录，由 `.gitignore` 的 `/keys/`、`*.key` 等规则排除提交；口令文件为 `keys/keystore.properties`，同样被排除。四个 Secret 均未配置时，Android 产物为 debug 包。

## 7. 本地命令

| 命令 | 作用 |
|---|---|
| `pnpm version:current` | 打印当前版本号 |
| `pnpm version:set 0.2.0` | 同步写入五处版本号 |
| `pnpm version:check` | 校验五处版本号一致，不一致退出码 1 |
| `node tools/release/plan.mjs --ref=refs/heads/beta --event=workflow_dispatch --channel=beta --existing-tags=v0.1.0-beta.1` | 预览渠道、标签与构建引用 |
| `node --test tools/release/plan.test.mjs tools/release/ci-gate.test.mjs` | 发布规则与 CI 闸门自测 |
| `node tools/legal/collect-licenses.mjs --check` | 校验第三方许可证清单与依赖一致 |
| `powershell -File tools/setup/make-android-keystore.ps1` | 生成本地签名密钥库到 `keys/` |
| `powershell -File tools/verify/verify-all.ps1` | 三端产物与测试总校验 |
