# 03 平台与构建

## 1. 三端运行环境与产物

| 端 | 运行环境 | 本地存储 | 产物 |
|---|---|---|---|
| Web | 浏览器，同源静态站点 | IndexedDB | `apps/web/dist` 静态包，入口 `index.html` 与 `mini.html` |
| Windows | Windows x64 + WebView2；Tauri 2 壳（紧凑条 + 托盘） | SQLite | 独立 exe、NSIS 安装包、便携 zip |
| Android | `minSdkVersion 24`、`targetSdkVersion 36`；Capacitor 壳 + Kotlin 小组件 | SQLite | APK（`assembleDebug` / `assembleRelease`） |

- Web 开发服务器：`pnpm -C apps/web dev --host 127.0.0.1`；默认只绑 `localhost`。
- 教务抓取的 HTTP 通道：Windows 走 `tauri-plugin-http`，Android 走 `CapacitorHttp`，Web 走浏览器 `fetch`。
- Android 小组件规格：2×2 下一节课、4×2 今日课表、4×4 一周概览、2×2 考试倒计时。
- 小组件配色走 Web 写入的快照 `colors`：`ink`/`muted`/`surface`/`accent` 随主题预设与明暗模式变化，`danger` 为 A-15 兼容字段；字段名由 `tools/verify/check-widget-contract.mjs` 与 `WidgetStore.kt` 双向校验。卡面底色用 `surface` 动态上色，旧快照没有该字段时回退三态 drawable。
- 打包产物只留在本地：`apps/web/dist`、`apps/desktop/src-tauri/target/release`、`apps/mobile/android/app/build/outputs/apk`、`out-local`。

## 2. 工具链版本要求

| 组件 | 版本 | 用途 |
|---|---|---|
| Node | ≥ 24 | 原生 TypeScript 类型擦除；`node --test` 直接执行 `.ts` |
| pnpm | 12.6.0（由 `packageManager` 固定） | 工作区依赖与脚本 |
| Rust | 1.99（stable 工具链） | Tauri 2 桌面壳 |
| JDK | 21 | Capacitor 插件与 Android 的 Java 21 工具链 |
| Android SDK | `platforms;android-36`、`build-tools;35.0.0` | Android 与小组件构建 |
| Gradle | 8.14.3（Android 工程 wrapper 自带） | Android 构建 |
| Python | ≥ 3.13 | `tools/schema-check` 与工作流 YAML 校验 |
| WebView2 | 系统自带运行时 | Windows 界面渲染 |

### 2.1 环境变量

| 变量 | 用途 |
|---|---|
| `JAVA_HOME` | 指向 JDK 21 安装目录 |
| `ANDROID_HOME` | 指向 Android SDK 目录；`aapt2` 与 `apksigner` 从这里取 |
| `DT_CHANNEL` | 注入渠道，取值 `dev` / `beta` / `release`，未设置时按 `dev` |
| `DT_VERSION` | 注入构建版本号，覆盖 Android `versionName` |
| `DT_VERSION_CODE` | 注入 Android `versionCode` |
| `ANDROID_KEYSTORE_PATH` | 签名密钥库路径（另有 `ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`） |

- 路径写法：JDK 用 `<JDK 安装目录>`，Android SDK 用 `<Android SDK 目录>`，用户级目录用 `%LOCALAPPDATA%`、`%APPDATA%`。

## 3. 目录结构

| 路径 | 内容 |
|---|---|
| `apps/web` | 界面与平台存储驱动；`src/design` 设计令牌、`src/components` 组件库、`src/lib` 工具、`smoke` 冒烟入口 |
| `apps/desktop` | Tauri 2 壳、托盘与窗口配置；`src-tauri` 为 Rust 工程 |
| `apps/mobile` | Capacitor 壳与 Android 小组件；`android/` 为 Gradle 工程 |
| `packages/core` | 数据模型、存储抽象、展开、提醒、检索、导入导出、页面识别、备份、同步；`src/schema` 为迁移 SQL |
| `tools/schema-check` | 建表 SQL 的跨引擎校验 |
| `tools/design` | 设计令牌导出与无障碍校验 |
| `tools/release` | 版本号同步、构建时间戳、发布规则、Android 签名包脚本 |
| `tools/setup` | Rust、Android SDK、JDK、图标、签名密钥的安装脚本 |
| `tools/legal` | 第三方许可证清单生成与校验 |
| `tools/verify` | `verify-all.ps1`、`smoke-ui.mjs`、`check-workflows.py` |
| `docs` | 规范与记录 |
| `.github/workflows` | `ci.yml`（检查）与 `publish.yml`（发版） |
| `keys` | 本地签名材料，不入库 |
| `out-local` | 本地打包产物 |

## 4. 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装工作区依赖 |
| `pnpm -C apps/web dev --host 127.0.0.1` | 启动 Web 开发服务器 |
| `pnpm -C apps/web build` | 构建 Web 静态包（`index.html` + `mini.html` 双入口） |
| `pnpm -C apps/desktop exec tauri build` | 构建 Windows exe 与 NSIS 安装包 |
| `pnpm -C apps/desktop exec tauri build --no-bundle` | 只出独立 exe |
| `pnpm -C apps/mobile exec cap sync android` | 同步前端产物与插件到 Android 工程 |
| `pnpm -C apps/mobile run build:android` | 同步后执行 `gradlew.bat assembleDebug` |
| `pnpm android:dev` / `pnpm android:release` | 调 `tools/release/build-android-release.ps1` 打签名 APK |
| `pnpm test` | 全部单元测试 |
| `pnpm typecheck` | 工作区全部类型检查 |
| `pnpm ui:smoke` | 界面冒烟（jsdom 渲染与切页） |
| `powershell -File tools/verify/verify-all.ps1` | 19 项总校验 |
| `powershell -File tools/build-local.ps1` | 本地打包，默认 dev 渠道 + debug 构建 |
| `pnpm version:set 0.2.0` / `pnpm version:check` | 同步 / 校验五处版本号 |

- `build-local.ps1` 参数：`-Channel dev|beta|release`、`-Artefact zip|nsis`；产物落在 `out-local/`。
- `-Artefact zip` 产出 `DawnTick-<version>-<channel>-windows-x64-portable.zip`，包内为 `DawnTick.exe` 与 `README-portable.txt`。
- 脚本用前端哈希资源名校验 exe 是否嵌入前端产物，未嵌入直接报错。

## 5. 版本号同步的 5 处位置

| 位置 | 字段 | 写入方 |
|---|---|---|
| `package.json` | `version` | 唯一来源，手工修改 |
| `apps/web/package.json` | `version` | `tools/release/version.mjs` |
| `apps/desktop/src-tauri/tauri.conf.json` | `version` | `tools/release/version.mjs` |
| `apps/desktop/src-tauri/Cargo.toml` | `[package] version` | `tools/release/version.mjs` |
| `apps/mobile/android/app/build.gradle` | `versionName` / `versionCode` | `tools/release/version.mjs` |

- `versionCode = major*10000 + minor*100 + patch`；当前 `0.2.0` → `versionCode 200`。
- 升版：`pnpm version:set <X.Y.Z>` 一次写五处；`pnpm version:check` 校验一致，不一致退出码 1。
- 构建时覆盖：`DT_VERSION` 写 Android `versionName`，`DT_VERSION_CODE` 写 `versionCode`（自 2024-01-01 起的分钟数，随时间单调递增）。

## 6. 渠道与产物命名

| 渠道 | 来源分支 | 构建类型 | 标签 |
|---|---|---|---|
| dev | `dev` | debug（Windows `--debug`、Android `assembleDebug`） | 固定 `dev-latest`，滚动覆盖 |
| beta | `main` | release | `vX.Y.Z-beta.<n>` |
| release | `main` | release | `vX.Y.Z` |

| 产物 | 命名 |
|---|---|
| NSIS 安装包 | `DawnTick-<version>-<channel>-windows-x64-setup.exe` |
| 免安装包 | `DawnTick-<version>-<channel>-windows-x64-portable.zip` |
| Android 包 | `DawnTick-<version>-<channel>-android.apk` |
| Web 静态包 | `DawnTick-<version>-<channel>-web.zip` |
| 校验文件 | 发布产物附一个 `SHA256SUMS.txt`，`sha256sum` 格式，一行一个产物 |

- 产物名只用 ASCII 与英文名 `DawnTick`；中文名只用在 Release 标题。
- dev 的 `<version>` 带构建时间戳（`yyyyMMddHHmm`，本地时间），例如 `0.1.0.202510131430`；beta 与 release 为 `X.Y.Z`。
- 三端产物由同一份内置预设快照在打包期内联。

渠道、标签与密钥的完整规则：[发布与版本](06-发布与版本.md)。
