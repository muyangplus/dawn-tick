## 1. 产品定位

**晓刻**：面向学生与轻量日程用户的课表 / 日程提醒工具。

- 核心价值：**课表导入一次，多端同步，课前准时提醒，桌面小组件随时看。**
- 目标用户：大学生、中学生、研究生、教师。
- 核心场景：看课表、导课表、被提醒、看小组件。
- **新增核心要求：轻量化**（D32）。

## 2. 核心功能范围

| 模块 | 功能 | 本期调整 |
|---|---|---|
| 课表 | 周视图、今日视图、课程详情、颜色标记 | — |
| 导入 | CSV/Excel、ICS、手动添加 | **教务系统在线抓取推迟**（D30） |
| 提醒 | 课前 5/10/15/30 分钟、自定义、节假日跳过 | — |
| 小组件 | 下一节课、今日课表、一周概览、考试倒计时 | **Windows 改为悬浮小窗 + 托盘**（D28）；Android 保留（D28） |
| 日程 | 考试、待办、调课、临时日程 | — |
| 多端 | Web、Windows、Android | Tauri 2 / Capacitor（D25/D26） |
| 同步 | 离线优先，多端自动同步 | **推迟到下一期**（D3），但字段已预留（D23） |

支持便捷调休 / 调日程。

## 3. 架构原则

1. **离线优先**：本地 SQLite 是真相来源，联网后按 `pull → push → pull` 同步。
2. **一套 DDL 跑三端**：Web(SQLite-WASM+OPFS) / Windows(tauri-plugin-sql) / Android(Capacitor SQLite)，
   建表 SQL 只用标准 SQLite 语法（详见 `01` 第 5 节）。
3. **轻量化**：不引重量级依赖，优先自写（如课表网格用 CSS Grid 自绘，不用现成日历组件）。
4. **业务代码不直连数据库**：统一走数据访问层。

### 4.3 技术栈与三端（详见 `02-技术选型对比.md`）

| # | 议题 | 决策 |

| D24 | 技术栈总纲 | **三端统一 Web 栈（React + TypeScript）**，界面代码共用 |

| D29 | Windows 关应用后提醒 | **常驻托盘 + 开机自启**（应用不退出），规避官方计划通知的 5 分钟投递窗口 |
| D32 | 轻量化 | **不设量化指标**，先把架构做轻（不引重量级依赖，能自写就自写） |
